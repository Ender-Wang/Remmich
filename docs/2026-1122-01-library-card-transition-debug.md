# Library card transition debugging

All Library hub cards now use the iOS navigation zoom, with the title and controls inside each destination. UIKit handles return input. The app reconciles a stale navigation path when UIKit confirms the Library grid is visible again.

The native rollout trace exercised 11 enabled cards. Each interrupted opening returned to path depth zero. On Device accepted the sampled grid drag after return, and two earlier drags began before the returns for Memories and Places had settled. The Recently Added sampler reached its deadline before UIKit reported the cancellation. Folders and Shared Links use the shared route when enabled. The temporary card probes were removed after the capture.

The November 21 device run reproduced three separate symptoms. The rollout capture verified the scroll fix on the cards exercised. The temporary traces and touch probe were removed afterward. The trace names below describe the captures used during the investigation.

## 1. The first scroll after dismissal is ignored

- Open a Library card. Swipe back and start a new vertical drag as soon as the card looks settled. The Library stays still on the first attempt and scrolls after a brief wait. Repeat with the back button to compare an interactive dismissal with a button-driven one.
- The latest build has no app scroll lock in the return path. The four coordinated returns kept the same observed scroll offset through their completion. The hub remounted 813–1,206 ms before that completion. That interval measures the navigation lifecycle. The capture has no touch timestamps, so it cannot establish when the first drag was intercepted.
- Three next-card taps were handled 10–60 ms before the preceding return completed. The coordinator therefore permits some hub input before completion. The missing evidence is how it handles the scroll gesture.
- Record the first vertical drag separately from the back gesture. Compare touch delivery to the window, the hit-tested view, and the Library scroll recognizer. The first new drag after the card visually settles should move the Library in the same gesture.
- The Debug-only `hub return input` trace recorded the touch timestamp and target, the first vertical movement, the scroll recognizer state, and the offset for four seconds after dismissal began.

### Follow-up capture and comparison with Photos and Videos

- The 17:43 capture records two interrupted returns. The first vertical drag after each logged return reached the Library scroll view and moved it. The recognizer and scroll view were enabled throughout the capture.
- Two vertical drags during the second card presentation hit a SwiftUI `PlatformGroupContainer` outside the Library scroll view. They began about 780 ms and 347 ms before that card's dismissal callback. The Library recognizer stayed possible and the offset did not move. The log cannot establish what was visible when those two touches began. The probe still carried the previous card's ID until the new dismissal callback armed its replacement.
- Photos and Videos clear the asset viewer's input ownership as soon as dismissal commits. The returning image stays mounted in a separate, non-interactive overlay and follows the moving thumbnail. Library cards use native `NavigationStack` zoom. The title overlay already ignores touches, while the native destination controls when the hub can receive them.
- Use the same input and animation separation if a visually settled Library return still routes a fresh drag outside the hub. For the next comparison, let the card finish opening, dismiss it, and drag vertically through the cards as soon as they appear settled. Compare swipe and button dismissal with the same Debug build.

### Completed opening versus interrupted opening

- In the comparison capture, both returns after a completed open accepted a new scroll pan 777–823 ms before UIKit reported the return complete. Waiting for all return animation callbacks is unnecessary. During the interrupted open, a touch reached the card's navigation container before the logged return, while the first drag recorded after the return reached the hub. The reported difference is consistent with the navigation destination keeping touch ownership until UIKit hands it back. The trace cannot identify the exact visual landing frame of the interrupted return.
- The asset viewer reverses its existing opening animation from the current position when the user commits a dismissal. It gives the timeline input immediately by clearing the active presentation ID. The same visual surface then finishes the return without hit testing. It tracks a moving thumbnail, fades if no return target exists at dismissal, and removes the return surface if its tracked source disappears.
- The equivalent Library design is an app-owned presentation for the first card open. A committed dismissal would release the hub immediately and retarget the moving card to its current source, including if the open is still in progress. A cancelled gesture would keep the detail interactive. Cleanup would be scoped to that presentation so a quick reopen could not be affected by the previous completion. Nested detail navigation could stay native.
- Start the comparison with On Device. Verify an early reversal, a normal dismissal, a cancelled swipe, an immediate scroll, and a quick open of another card. The prototype should keep the same card zoom motion and support Reduce Motion before extending the approach to other cards.
- The On Device prototype uses a fixed-layout detail inside an app-owned zoom. Back commit releases input and accessibility immediately. The passive return follows the source card as the hub scrolls, and an old return can only clean up its own presentation. Look for `On Device return committed` and `hub return input` in the device trace. The prototype blends the card into its detail header during the zoom. The separate title flight and background flash are tracked below.
- The 17:57 capture reopened the same second-row card three times. Its source rect and the hub card order identify it as Recently Added. Every attempt used `native opening began`; none logged `On Device return committed`. The local device build created just before launch contains the On Device prototype. This run reproduces the native path and leaves the pilot unverified.
- The next capture shows three interrupted opens of Memories. In the first, the title was back at its card roughly 900 ms before the dismissal callback. In the other two, vertical drags still hit outside the hub after the title was within five points of its source. After the last dismissal callback, the next recorded drag moved the hub by about 54 points. This confirms that the native title can visually land while the destination still owns touch routing. The On Device pilot has its own return marker and still needs a capture.
- The November 22 capture verified touch routing after all five On Device returns. The first new drag reached the hub and moved it each time, with touch-downs 188–321 ms after `On Device return committed`. Those intervals measure when the gestures were attempted. The trace does not record when the opening or return animation visually settled. The same capture still shows interrupted native returns with touches routed outside the hub before dismissal.
- All first-level Library cards now share the pilot's zoom and input handoff. Native navigation within a card handles deeper folder, shared-link, and fixture destinations. The rollout capture matched `hub card opening`, `hub card return committed`, and `hub return input` by presentation ID.
- The rollout capture records 13 committed returns across 11 hub cards. Every first touch reached the hub. The 10 first touches that were vertical drags all started the scroll recognizer and changed the offset. The other three were taps on Partners and Archive returns. The earliest successful drag began 208 ms after commit, and the shortest open-to-commit interval was 435 ms. The nested Places timeline closed before the Places hub card. Folders and Shared Links were outside this capture.

## 2. Earlier title flight

The card label stays in the card layout, and the detail page uses its own navigation title. The title flight described below was removed from Library cards and directory entries.

- Open a Library card and watch the title as it finishes moving into the header. The reported glitch is a small shift after arrival. Repeat from a scrolled Library position and distinguish this from the earlier replay on dismissal.
- The four completed opens in the latest capture end at the measured header rectangle. The three interrupted returns report `local return already at source` and skip replaying the return animation. Matching rectangles cannot establish that the flying text and the native header draw at the same baseline or that only one copy is visible through the handoff.
- Check the last visible frame of the moving title and the first visible frame of the native label. The text should keep the same position through the handoff, with one visible title throughout.

## 3. The header background flashes a second time

- Open a Library card and watch the top strip as the title settles. The reported second change in shade persists on the latest build.
- All seven card destinations report `suppressed for card destination`. The older trace had a separately animated destination blur. The latest trace rules out that view as the sole cause of the remaining flash. The Library hub backdrop still unmounts around the end of a completed open. The trace does not show the final compositing of that backdrop.
- Isolate the hub backdrop and navigation chrome during the final frames. Verify that the backdrop appears and disappears through one continuous transition without an extra darkening or flash.
